# UI 设计检查清单

用于设计完成后的人工检查或 AI 设计审查。先列出具体问题与位置，再提出修改建议；不要只给“更高级”“更美观”等模糊评价。

## 视觉与布局

- [ ] 页面有明确的视觉层级，重点信息容易找到。
- [ ] 同类型元素对齐一致，没有无理由的错位。
- [ ] 间距遵循稳定的尺寸体系，内容分组清楚。
- [ ] 字体大小、字重、行高和颜色构成清晰层级。
- [ ] 圆角、边框、阴影遵循统一组件规范。
- [ ] 颜色用途明确，普通文字与辅助文字都可读。

## 交互与内容

- [ ] 主操作与次操作容易区分。
- [ ] 点击、加载、错误、禁用等必要状态齐全。
- [ ] 表单错误信息明确，不能只依靠颜色提示。
- [ ] 空数据、无权限、加载失败等界面有适当说明。
- [ ] 复用了项目已有组件及其主题变量。
- [ ] 文案自然清晰，避免不必要的术语。

## 适配与可访问性

- [ ] 常见屏幕宽度下页面没有溢出或遮挡。
- [ ] 长标题、长文本和数据异常值不会破坏布局。
- [ ] 可以清楚识别键盘焦点。
- [ ] 检查文本对比度及必要的非文本对比度。
- [ ] 关键操作具备可识别的名称和足够的点击区域。

## AI 审查输出格式（建议）

每个问题按以下内容说明：

1. **位置**：页面、组件或元素。
2. **问题**：可以直接观察到的现象。
3. **影响**：对阅读、理解或操作的具体影响。
4. **修改建议**：明确的样式或交互调整。
5. **优先级**：高／中／低。

优先修复影响使用与可读性的问题，再处理视觉细节。
